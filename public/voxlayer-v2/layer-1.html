No. Layer 1 never calls Gemma or any model. It only schedules which state-machine edge needs a training row.
A state = where the call is right now (e.g. TAKE_MESSAGE).
An edge = one legal move from state A to state B (e.g. INTENT_CLASSIFY → TRANSFER).

Design target: ~100 training examples per edge, not "100 random calls and hope we covered transfer."
  • Open state_machine_v1.json from Layer 0 config
  • Read initial_state (usually INTENT_CLASSIFY)
  • For each state, read transitions
  • Flatten nested branches (business_hours, after_hours) into simple arrows
  • Build Edge objects: edge_id, from_state, to_state, events
Receptionist has ~20 edges total.
For each edge: create transition_quota jobs (default 100). Optional overrides for rare edges. Optional total_rows cap. Shuffle job order using seed from config.

Output: a list of WorkUnit objects — one per training row to create.
One work unit = one training row (v2 default). Example:
  • scenario_id: acme-plumbing-CONFIRM_SLOTS__SEND_MESSAGE-0042
  • edge: CONFIRM_SLOTS → SEND_MESSAGE
  • index: 42 of 100 for this edge
  • meta.entry_depth: 4 (prefix turn count in output — reporting only)
  • path_class: happy (optional tag for reporting)
Layers 2–5 each consume one work unit at a time.
