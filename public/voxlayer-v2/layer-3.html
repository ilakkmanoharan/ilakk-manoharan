Layer 3

Assembler — the envelope

"Production-shaped messages[]"

Layer 3 takes plain dialogue from Layer 4 and runtime facts from Layer 2 and wraps them in the exact chat format sipagent uses in production. Output is messages[] with [skillset_runtime_context] on user turns and <next_state> on assistant turns. This layer is kept as-is for v2.

Layer 3 wraps spoken words in the production training format — system prompt, runtime JSON badges, alternating roles, and next_state tags — without inventing dialogue.
Input: SkillsetRuntime, history[] (prefix pairs), target user + assistant text, meta fields.

The training label — usually the target assistant line: Thank you, I'll send that message now.<next_state>SEND_MESSAGE</next_state>. Training uses full messages[] + output, not a duplicate legacy instruction string.
Same string format as live calls. When sipagent changes wrap rules, the generator follows one source of truth. Reduces train/serve drift. Uses build_skillset_user_turn_content from sipagent/skillsets/prompt.py.
  • Exactly one system message first
  • Roles alternate after system (user, assistant, user, assistant…)
  • Every user message has [skillset_runtime_context] and elapsed ms
  • Target output has valid next_state matching Layer 1's planned edge
  • Entity consistency — company/caller in text match meta and runtime JSON
  • No leakage across scenario_ids
Validator enforces these in validation/inspector.py.
